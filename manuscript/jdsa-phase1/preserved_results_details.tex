\subsection{Structural and Solver-Backed Validation}
\label{app:restricted-details}

Core metrics are solver-free. Three historical restricted studies use a different grounding implementation: optimization-role relation repair, rather than the headline typed-greedy configuration. The 60-case study takes the first original queries with 2--8 gold scalar parameters; the 269-case study selects instances with reference solver code. Their saved aggregate rates are retained, but their names must not be interpreted as stronger validation than the code performs.

The legacy field \texttt{structural\_valid} is a \emph{coverage/type proxy}: it is true when the predicted eligible inventory is empty, or when coverage and type match are both at least 0.8. Unlike main-benchmark readiness, this proxy treats an empty inventory as passing. It does not inspect linearity, decision variables, objective correctness or constraint well-formedness. The field \texttt{parseable\_model\_artifact} checks only that objective and constraint metadata are nonempty. \texttt{instantiation\_complete} combines that presence check, full predicted-scalar coverage, and absence of expected parameter names in the rendered description; it does not require compatible types or validate numerical values. These subset inventories use numeric status in the predicted schema's parameter record, not the main benchmark's intersection with the query's gold keys.

The 20-case solver study is a separate, compatibility-filtered execution check. Its executable flag means that reference code finishes without an exception and leaves a model object. The two legacy success/feasibility flags both test the shim's status 2, set after a successful SciPy optimization with a returned solution; they are not independent outcomes. The objective-produced flag checks for a non-null objective value. Predicted-template parameter records initialize execution: unfilled scalars and structured data retain reference values, and filled parameters originally typed as integers are rounded. Thus these are gold-assisted executions of reference programs, not complete programs generated from the query alone.

\subsection{Computational Complexity and Runtime}
\label{app:runtime-details}

The recorded lexical backbone has a small computational footprint on this catalog. TF--IDF fits a sparse vectorizer once over the $M=335$ schema documents and, for each query, transforms the query and scores it against the full catalog matrix by sparse cosine similarity (\textsc{scikit-learn}); with fixed small $M$, the lexical query path consists of sparse vector operations and does not execute a neural encoder. Rule-based extraction is linear in query length. Typed-greedy assignment scans candidates in $O(|\mathcal{P}|\cdot|\mathcal{T}|)$ comparisons in the (typically small) numbers of eligible slots and mentions. A historical timing summary for TF--IDF + ratio-aware typed greedy (331 queries, \texttt{PYTHONHASHSEED=0}) records wall time $1.09$\,s ($3.29$\,ms/query) with peak RSS $\approx 198$\,MB. The recorded scope excludes BGE-M3 embedding load/compute and remote LLM baselines; the single retained timing summary is contextual, not a reproducible timing distribution or cross-method efficiency benchmark.


\subsection{Challenges in Numerical Mention Grounding}
\label{app:occurrence-boundary}

The stored-value failures motivate an occurrence-level relationship audit; they do not by themselves identify semantic error causes. A mention has a source occurrence, not just a magnitude: for the auxiliary relation audit, write $m=(a,b,v)$ for its half-open character interval and normalized value, and $r=(q,m,p)$ for the proposed relation to parameter $p$. This diagnostic representation does not imply that the historical typed-greedy outputs retained character-aligned assignment traces. Two occurrences with the same $v$ can refer to different resources; one occurrence may also legitimately support several declarations. No-reuse assignment is therefore an experimental restriction, not a general law of optimization modeling. Implicit objective or identity terms introduce a different problem: there may be no lexical number to align. Their absence cannot be converted automatically into a verified null relationship.

Historical weak-label learning used numerical equality to choose a first matching mention. Such targets do not distinguish repeated values, resource roles or incomplete formulations. Earlier neural and classifier-plus-assignment runs are documented, but their supervision and evaluation do not support a clean conclusion that learning cannot improve grounding. The saved P0 comparison shows no coarse-readiness gain from its exact-assignment condition; missing prediction traces and evaluation-derived splits prevent a broader semantic interpretation. Supplement, Section~\ref{app:supervision-audit} distinguishes completed negative results, inconclusive runs and blocked proposals.


\subsection{Preserved Statistical and Robustness Audit History}
\label{app:statistical-history}

All inferential analyses here are retrospective. Query identities are paired across methods; the correction-only reanalysis reuses the existing 327 delexicalized text groups for all 331 original queries. It reports marginal paired group-percentile bootstrap intervals ($B=10{,}000$, NumPy seed 42), exact groupwise method-swap tests on integer count differences, and Holm adjustment over the 16 reported retrieval/readiness contrasts \cite{holm1979followup}. That family contains five main-table contrasts, the BGE--TF--IDF retrieval contrast, and ten ordinary/Strict contrasts against the five grounding alternatives. The factorial's separate 240-endpoint family remains unchanged. Grouping is heuristic and does not remove all dependence or prior benchmark exposure.

Table~\ref{M-tab:nlp4lp-significance} replaces the legacy significance summaries using the same saved observations. The earlier uncentered bootstrap sign-tail values were not null-calibrated tests; the BGE intervals were shifted randomization quantiles rather than sampling confidence intervals. Floating-point ties also affected those BGE p-values. Historical statistic files are retained in the correction record. The ratio-aware extraction gain remains $8/331=0.0242$; its exact paired/group test is $p=0.0078125$ and the adjusted value is $0.0302$. These tests concern coverage/type diagnostics, not numerical correctness.
The historical sanitized-retrieval aggregates (Table~\ref{tab:nlp4lp-overlap}) report preserved or improved rates after stripping numbers and/or stopwords. Without the original per-condition predictions, this is limited support for robustness to that transformation, not independent confirmation of its mechanism. The diagnostic uses a closely matched index (331 documents excluding four filler templates; no \texttt{doc\_id} tokens), so TF--IDF/BM25 baseline cells differ slightly from Table~\ref{M-tab:nlp4lp-retrieval-main} while LSA matches exactly ($0.8459$). A Jaccard-overlap stratification places 327/331 queries in a high-overlap bucket (TF--IDF R@1 $0.9174$); the medium-overlap bucket has only 4 queries and is reported only as a qualitative caveat.

To check whether wrong schemas can inflate ordinary InstantiationReady via smaller eligible-slot sets, a repository diagnostic of selective schema reranking raised ordinary readiness from $257/331$ to $265/331$, but $6$ of $8$ newly ready queries used an incorrect schema. We therefore use the schema-gated readiness measure as a robustness check (Table~\ref{M-tab:strict-instready}). The gate removes 10 TF--IDF queries in both extraction configurations and widens the descriptive TF--IDF--Oracle readiness gap from $0.0483$ to $0.0785$. The corrected ordinary/Strict adjusted p-values are $0.0028$ and $<0.001$, respectively; neither metric tests scalar values.
